# Классификатор спама для Telegram

Telegram-бот на Java / Spring Boot отправляет русскоязычный текст в Python API и отвечает пользователю в зависимости от результата классификации.

Проект демонстрирует интеграцию Telegram, Java-приложения и готовой языковой модели по HTTP. Это прототип для локального запуска: бот отвечает на сообщения, но не удаляет их и не блокирует пользователей.

[English version](README.md) · [Java-бот](src/main/java/com/example/anti_spam_telegram_bot/AntiSpamTelegramBot.java) · [Python API](app.py) · [Карточка модели](https://huggingface.co/ruSpamModels/ruSpam_big)

## Модель и вклад проекта

Используется готовая модель **[`ruSpamModels/ruSpam_big`](https://huggingface.co/ruSpamModels/ruSpam_big)** от ruSpamModels. В репозитории находятся код интеграции и выполнения предсказаний. Обучения модели и собственной оценки её качества здесь нет; сведения автора модели об обучающей выборке не являются результатами этого проекта.

## Как это работает

1. Java-бот получает обновления Telegram через long polling и обрабатывает текстовые сообщения.
2. `WebClient` отправляет `POST /predict` с полем `text`. Обработчик Java ожидает ответ через `.block()`.
3. Python загружает модель при импорте приложения и использует CUDA, если она доступна, иначе CPU.
4. Текст токенизируется с ограничением в 512 токенов. К выходу модели применяется sigmoid; при значении `>= 0.5` возвращается `spam: true`.
5. Бот отправляет предупреждение о спаме или приветствие с исходным текстом.

Стек: Java 17, Spring Boot 3.4.3, Telegram Bots 6.5.0, Spring WebFlux; Python, FastAPI, Pydantic, Uvicorn, PyTorch и Transformers. Java собирается Maven Wrapper, Python-зависимости перечислены в `requirements.txt`.

## Локальный запуск

Нужны JDK 17, Python 3 с `venv` и доступ к Telegram и Hugging Face. Версии Python-зависимостей пока не закреплены; совместимость зависит от установленных версий пакетов. Maven Wrapper загрузит Maven при первом запуске.

Создайте своего бота через [BotFather](https://core.telegram.org/bots/features#botfather). Ознакомьтесь с условиями доступа к [модели](https://huggingface.co/ruSpamModels/ruSpam_big) и примите их на Hugging Face; создайте read-токен с доступом к модели. При первом запуске Python загрузит файлы модели.

Команды ниже предназначены для macOS / Linux. В Windows используйте `.venv\Scripts\activate`, `mvnw.cmd` и синтаксис переменных окружения своей оболочки.

```bash
git clone https://github.com/philsyr/telegram-antispam-bot.git
cd telegram-antispam-bot
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

**Терминал 1 — Python API:**

```bash
source .venv/bin/activate
export HUGGINGFACE_TOKEN="your_hugging_face_read_token"
python -m uvicorn app:app --host 127.0.0.1 --port 8001
```

Проверьте API перед запуском бота:

```bash
curl -sS http://127.0.0.1:8001/predict \
  -H 'Content-Type: application/json' \
  -d '{"text":"Привет! Во сколько встречаемся?"}'
```

Ответ должен содержать `spam` и `score` без поля `error`. Работающий HTTP-сервер ещё не означает, что модель загрузилась. Интерактивная документация доступна на [localhost:8001/docs](http://127.0.0.1:8001/docs).

**Терминал 2 — Java-бот, из каталога репозитория:**

```bash
export BOT_TOKEN="your_telegram_bot_token"
export BOT_NAME="your_bot_username"
export MODEL_SERVICE_URL="http://127.0.0.1:8001"
./mvnw spring-boot:run
```

Отправьте текст в личный чат **своему боту**. При обнаружении спама ответ начинается с `Обнаружен спам! Сообщение: ...`, иначе — с `Hello, <first name>! You said: ...`. Отдельные примеры сообщений не являются оценкой точности; конкретный результат зависит от модели.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Обязательный токен Telegram для Java-бота |
| `BOT_NAME` | Переопределяет `bot.name`; имя вашего бота без `@` |
| `MODEL_SERVICE_URL` | Адрес Python API; по умолчанию `http://127.0.0.1:8001` |
| `HUGGINGFACE_TOKEN` | Токен для доступа к модели |
| `HF_TOKEN` | Альтернатива; используется, если не задан `HUGGINGFACE_TOKEN` |

В [`application.properties`](src/main/resources/application.properties) используются ссылки на переменные окружения. Файл `.env` **не загружается автоматически**: экспортируйте переменные в той оболочке, которая запускает соответствующий процесс. Не сохраняйте настоящие токены в отслеживаемых файлах.

## API

`POST /predict` принимает JSON с обязательным строковым полем `text`:

```json
{"text": "Кликни здесь и выиграй приз!"}
```

Пример формы ответа; число ниже не получено измерением:

```json
{"spam": true, "score": 0.75}
```

`score` — выход sigmoid, а не проверенная вероятность и не показатель точности проекта. Если модель недоступна, API сейчас возвращает HTTP 200, `spam: false`, `score: 0.0` и поля `error` / `detail`. Такой ответ означает ошибку предсказания.

## Ограничения и дальнейшая работа

- Java-клиент читает только `spam`, поэтому недоступная модель может привести к обычному приветствию. При транспортной ошибке к приветствию добавляется сообщение об ошибке. Приоритетное улучшение — различать успешную классификацию и недоступность сервиса.
- Java-обработчик блокируется на время запроса. Явные тайм-ауты, повторы запросов и ограничение частоты не настроены.
- Порог фиксирован на `0.5`, длинный текст обрезается. В репозитории нет собственных измерений precision/recall, задержки и пропускной способности.
- У API нет аутентификации; инструкция запуска привязывает его к loopback. Конфигурация развёртывания, хранилище и действия модерации отсутствуют.
- Единственный Java-тест поднимает контекст Spring и при этом пытается зарегистрировать бота в Telegram. Изолированных тестов обработчика и контракта API пока нет.

Сборка Java без запуска теста контекста:

```bash
./mvnw -DskipTests package
```

Эта команда проверяет сборку Java, но не доступ к Telegram, доступность модели или качество предсказаний.
